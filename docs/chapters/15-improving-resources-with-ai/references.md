# References: Improving a Resource with AI Agents

1. [Derivative work](https://en.wikipedia.org/wiki/Derivative_work) - Wikipedia - Explains how a work based on another is treated in copyright law. Background for the chapter's check of what a license allows before an agent changes a resource.

2. [Readability](https://en.wikipedia.org/wiki/Readability) - Wikipedia - Surveys what makes text easy to read, the formulas used to measure it, and their limits. Supports the chapter's reading-level fixes and the re-scoring that checks them.

3. [Continual improvement process](https://en.wikipedia.org/wiki/Continual_improvement_process) - Wikipedia - Describes ongoing, incremental improvement cycles such as plan, do, check, act. Frames the chapter's improvement plan and its re-scoring after each round of changes.

4. Refactoring: Improving the Design of Existing Code (2nd ed.) - Martin Fowler - Addison-Wesley (2018) - Fowler's discipline of making many small changes that preserve behavior, checking after each one, is the model for having an agent change one thing at a time and re-score.

5. Style: Lessons in Clarity and Grace - Joseph M. Williams and Joseph Bizup - Pearson - Williams's principle of making characters the subjects and actions the verbs gives a concrete method for rewriting dense prose. Useful for judging and directing an agent's reading-level edits.

6. [Alt Decision Tree](https://www.w3.org/WAI/tutorials/images/decision-tree/) - W3C Web Accessibility Initiative - A decision tree for choosing the right alt attribute for each kind of image. Lets a reviewer judge whether an agent's alt text suits the image's purpose.

7. [Pull Requests](https://docs.github.com/en/pull-requests/reference/pull-requests) - GitHub Docs - GitHub's documentation on proposing, reviewing, and merging changes. The standard way to let a person inspect every change an agent made before accepting it.

8. [Best Practices for Claude Code](https://code.claude.com/docs/en/best-practices) - Anthropic - Guidance for directing an AI coding agent, including giving it a check to verify its own work. The same practice applies when an agent edits an OER.

9. [Marking Your Work with a CC License](https://wiki.creativecommons.org/wiki/Marking_your_work_with_a_CC_license) - CC Public Wiki - Shows how to place a license notice on a work. This is the step needed when a revised version is published.

10. [git-diff Documentation](https://git-scm.com/docs/git-diff) - Git - Reference for showing exactly what changed between two versions of a file. Lets a reviewer see every line an agent altered before approving the change.
